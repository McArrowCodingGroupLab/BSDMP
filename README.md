## BSDMP (Binary Self-Describing Messaging Protocol)

i18n : [English](README.en.md) | [Русский](README.md)

BSDMP (Binary Self-Describing Messaging Protocol) — бинарный протокол для эффективной передачи структурированных данных между клиентом и сервером. Протокол использует самоописываемую структуру, позволяющую получателю интерпретировать данные без предварительного знания их формата.

## Общая структура сообщения

```c
struct BSDMPMessage {
    byte[4]  magic;           // Сигнатура формата: 'BSDM'
    BSDMPHeader header;       // Заголовок сообщения
    BSDMPDataBlock data;      // Блок данных (заголовки полей + фреймы), возможно сжатый
    byte[4]  crc;             // CRC от блока data (вне зависимости от compression)
}

struct BSDMPHeader {
    uint8_t version;           // Версия протокола (напр. 1)
    uint8_t extension;         // Версия расширений (для пользовательских расширений)
    uint8_t compression;       // Метод сжатия (0 = нет, 1 = gzip, и т.п.)
    uint8_t reserved1;          // Зарезервировано (для выравнивания)
    uint8_t  binary_flags[8];  // Пользовательские битовые флаги (8 байт = 64 булевых флага)
    uint32_t data_block_size;  // Размер блока data в байтах (возможно, после сжатия)
    uint8_t reserved2[8];       // Зарезервировано (для выравнивания до 16 байт)
}

struct BSDMPDataBlock {
    uint32_t frame_count;      // Кол-во кадров в блоке
    
    uint32_t fse_len;          // Длина маркера начала фрейма
    byte[fse_len] fse;         // Последовательность байт — начало фрейма
    
    uint32_t fee_len;          // Длина маркера конца фрейма
    byte[fee_len] fee;         // Последовательность байт — конец фрейма

    uint32_t title_len;        // Общая длина заголовков полей
    byte[title_len] title;     // Список описаний полей (title entries)

    BSDMPFrame[frame_count] frames; // Список фреймов (кадров)
}

(Повторяется field_count раз, как сериализованная последовательность внутри title)
struct BSDMPTitleEntry {
    uint16_t name_len;         // Длина имени поля
    byte[name_len] name;       // Имя поля (UTF-8)
    uint8_t type_code;         // Тип данных (см. enum типа — например, int, string, binary, и т.д.)
    uint8_t type_len;          // Кол-во байт, отведённых под field_len (обычно 1 или 2, может 4)
}

struct BSDMPFrame {
    byte[fse_len] fse;         // Маркер начала фрейма (повторение из data.fse)

    uint32_t frame_num;        // Порядковый номер фрейма
    uint16_t field_count;      // Кол-во полей в фрейме (может быть меньше или равно title_count)

    BSDMPField[field_count] fields; // Список полей

    byte[fee_len] fee;         // Маркер конца фрейма (повторение из data.fee)
}

struct BSDMPField {
    uint8_t title_index;        // Индекс в title (от 0 до title_count - 1)
    byte[type_len] field_len;   // Длина данных, `type_len` берётся из соответствующего title
    byte[field_len] data;       // Данные поля
}
```

## Методы сжатия (compression)

| Код | Метод сжатия | Описание |
| --- | ------------ | -------- |
| 0x00   | RAW          | Без сжатия |
| 0x01   | ZLIB         | Сжатие ZLIB |
| 0x02   | GZIP         | Сжатие GZIP |
| 0x03   | BZIP2        | Сжатие BZIP2 |
| 0x04   | LZMA         | Сжатие LZMA |

---

## Типы данных (type_code)

| Код | Тип данных | Формат |
| --- | ---------- | ------- |
| 0x01 | STRING | UTF-8 строка |
| 0x02 | INT | int64_t (8 байт, little-endian) |
| 0x03 | FLOAT | double (8 байт, IEEE754) |
| 0x04 | BOOL | 1 байт (0x00/0x01) |
| 0x05 | JSON | UTF-8 строка JSON |
| 0x06 | BINARY | Произвольные бинарные данные |

## Процесс кодирования

1. **Формирование заголовка (BSDMPHeader):**

   * `version` — указание версии протокола.
   * `extension` — версия расширения.
   * `compression` — выбранный метод сжатия.
   * `reserved` — выравнивание / резерв.
   * `data_block_size` — будет заполнено после сжатия блока данных.
   * `reserved` — выравнивание / резерв.

2. **Подготовка блока данных (BSDMPDataBlock):**

   * Установить `frame_count` — количество фреймов.
   * Установить `fse_len` и `fee_len`, задать байтовые маркеры `fse` и `fee`.
   * Сформировать `title`:

     * Для каждого поля задать `BSDMPTitleEntry`: `name_len`, `name`, `type_code`, `type_len`.
     * Итоговый заголовок сериализуется и записывается с указанием `title_len`.

3. **Кодирование фреймов:**
   Для каждого `BSDMPFrame`:

   * Начать с маркера `fse`.
   * Указать `frame_num` и `field_count`.
   * Для каждого поля:

     * `title_index` — индекс поля из заголовка.
     * `field_len` — записывается в `type_len` байт.
     * `data` — данные поля в `field_len` байтах.
   * Завершить маркером `fee`.

4. **Сжатие блока данных:**

   * Весь `BSDMPDataBlock` (от `frame_count` до последнего байта последнего фрейма) сжимается согласно `compression`.
   * Полученный сжатый блок сохраняется, а его длина записывается в `data_block_size`.

5. **Формирование итогового сообщения (BSDMPMessage):**

   * Префикс `magic = "BSDM"`.
   * Добавляется `BSDMPHeader`.
   * Добавляется сжатый `BSDMPDataBlock`.
   * Расчитывается CRC (например, CRC32) от `BSDMPDataBlock` (уже сжатого) и дописывается в конец.

## Процесс декодирования

1. **Проверка и чтение заголовка:**

   * Убедиться, что первые 4 байта соответствуют `"BSDM"`.
   * Прочитать `BSDMPHeader`.
   * Получить `data_block_size` и извлечь соответствующее количество байт из потока.

2. **Распаковка блока данных:**

   * Распаковать `BSDMPDataBlock` с использованием указанного в `compression` метода.

3. **Парсинг заголовка полей (title):**

   * Прочитать `frame_count`, `fse_len`, `fse`, `fee_len`, `fee`.
   * Прочитать `title_len`, извлечь заголовок.
   * Для каждого `BSDMPTitleEntry`:

     * Прочитать `name_len`, `name`, `type_code`, `type_len`.
     * Построить таблицу соответствий (index → entry).

4. **Обработка фреймов:**
   Для `frame_count` фреймов:

   * Проверить `fse` в начале фрейма.
   * Прочитать `frame_num`, `field_count`.
   * Для каждого поля:

     * Прочитать `title_index`.
     * Используя `type_len` из заголовка, прочитать `field_len`.
     * Прочитать `data` длиной `field_len`.
   * Проверить наличие `fee` в конце фрейма.
   * При необходимости построить карту фрейма (index → значение поля).

5. **Проверка целостности:**

   * Вычислить контрольную сумму (CRC) по сжатому `BSDMPDataBlock`.
   * Сравнить с сохранённым значением `crc`.

## Требования к реализации

* Все числовые значения в формате **little-endian**
* Строгое соблюдение размеров всех полей
* Обязательная проверка граничных условий и контроль размера буфера при чтении/записи
* Корректная обработка ошибок и отклонение некорректных структур
* Поддержка всех указанных типов данных, включая расширяемые поля

---

## Ограничения

* Максимальная длина имени поля: **65535 байт**
* Максимальная длина значения поля (по умолчанию): **255 байт**, **расширяется через `type_len`**
* Версия протокола: **3** (текущая)
* Размер основного заголовка (`BSDMPHeader`): **24 байт**
* Размер заголовка сообщения (`BSDMPMessage`): **32 байт** (4 magic + 24 header + 4 CRC)
* Поддержка заголовков полей (`title_block`) со структурой `name_len`, `name`, `type_code`, `type_len`
* `CRC`: 4 байта, CRC32 от блока данных (до сжатия или после — определяется compression-методом)
* Все фреймы обязаны включать `frame_num` и `field_len`
* Отсутствие `fse/fee` — начало/конец фрейма определяется структурно

- Magic-блок `BSDM` (версия 3) в начале пакета

- Расширение заголовка `title_block`: `name_len`, `name`, `type_code`, `type_len`

  - Python, Go, PHP (первая очередь)
